# 评测框架：七个维度与判定口径

> 这份文档回答一个问题：**怎么证明「这次改动真的变好了」**，而不是「我跑了几个问题感觉还行」。

代码在 `eval/`，跑法见 `eval/README.md`。这里只写设计口径。

## 一、为什么要七维

只报一个「准确率」有三个问题：**数字没有基线、失败不知道是哪一层的、稳定性看不见**。

所以拆成七维，每一维只回答一个问题：

| # | 维度 | 只回答 | 指标 | 常见造假方式 |
|---|---|---|---|---|
| 1 | 结果 | 答对了吗 | TSR | 只挑会答的题 |
| 2 | 检索 | 召回对不对 | recall@3、条数 | 条数够但内容错（「表面对」） |
| 3 | 证据 | 有没有胡言乱语 | grounding | 答案通顺但证据是编的 |
| 4 | 过程 | 真的成功了吗 | process_ok | 接口 500，模型猜了个答案 |
| 5 | 稳定性 | 每次都行吗 | pass@n / pass^n | 只跑一次就下结论 |
| 6 | 成本 | 快了吗、省了吗 | p50/p95、token | 只报平均不报长尾 |
| 7 | 安全 | 拦得住吗 | 拦截率 | 只测正常问题 |

## 二、两个最容易被骗的地方

### 1「表面对」：结果指标会骗人

后端接口 500 时，模型仍可能给出一个读起来很顺的答案。这时候：

- TSR：通过（关键词都在）
- process_ok：失败（trace 里有 5xx）
- grounding：接近 0（证据是空的）

所以 **结果、过程、证据必须分开算**，合成一个分数就看不出来了。`eval/datasets/fault.jsonl` 就是专门造这种场景的。

### 2 TSR 的口径

```
TSR = 首次即通过的用例数 / 用例数
```

- 不取「至少过一次」—— 跑 5 次过 1 次也算过，会把抖动藏起来；
- 稳定性单独用 `pass@n`（至少一次）与 `pass^n`（每次都过）表达，两个数字都要报；
- 一致性（答案完全相同比例）是第三个信号：变化大说明采样温度或检索有随机性。

## 三、静态数据与动态数据

| 类型 | 特征 | 判定方式 | 例子 |
|---|---|---|---|
| 静态 | 答案不随上下文变 | `must_contain` 关键词断言 | 「文档大小上限是多少」 |
| 动态 | 依赖上一轮 / 指代 / 记忆 | 同 session 内发 `follow_ups`，判最后一轮 + 是否指代正确 | 「超过这个大小怎么办」 |

**为什么必须分开**：静态题的分数高，常常是因为模型会「背常见问题」；动态题才看得出记忆与指代有没有真的接上。两者混在一起算平均，等于把最弱的一环藏起来。

## 四、工作方式：mock 锁死链路，live 出真数

```
mock  →  验证指标逻辑（两个 variant 必须跑出差异，否则指标失效）
  ↓
live  →  真跑 Agent，固定同一份语料 + 同一批用例
  ↓
对比  →  报告里永远是「A 相对 B」的差值，而不是孤立的一个分数
```

`--runs 5` 的意义：同一条用例跑 5 次，看 `pass@5` 与 `pass^5` 的差距。差距大说明系统不稳定（检索抖动、模型采样、工具超时），这时候单次运行的成绩没有意义。

## 五、线上与离线

| | 离线评测（本仓库） | 线上观测 |
|---|---|---|
| 数据 | 固定 39 条用例 | 真实流量 |
| 指标 | TSR / grounding / recall@k | 错误率、P95 延迟、转人工率、追问率 |
| 作用 | 改动前后对比，防回归 | 发现问题（这类问题往往不在用例里） |

**离线评测的价值是「防回归」，不是「证明效果好」**。真正的失败长什么样，只能靠线上反馈补用例 —— 每次线上出一个坏 case，就回填一条到 `datasets/`，这才是用例增长的正常方式。

## 六、错误修复率

除了 TSR，还应该单独统计 **「失败后被修好的比例」**：

```
错误修复率 = 上一版失败、这一版通过的用例数 / 上一版失败的用例数
```

它回答的是「这次改动到底修了什么」，比 TSR 涨了几个点更有信息量 —— 因为 TSR 可能因为「运气」涨（某几条随机过了），而修复率是按用例对齐的。

> 实现方式：两次 live 结果按 `case_id` 对齐，取 `run=0` 的记录比 `ok`。

## 七、当前的局限

- 39 条用例，其中 10 条的事实断言待核校（`needs_review`），所以**现在的数字只能用来比较版本，不能对外报绝对值**；
- grounding 是 token 重叠的下界，不理解同义改写，会低估真实忠实度；
- token 是字符折算，只能看相对变化；
- 没有接入 CI：需要先解决「CI 里没有模型 Key」的问题（可用 mock 跑指标回归，live 手动跑）。
